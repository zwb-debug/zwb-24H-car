# 03 调试与标定

> 顺序很重要：**先让每个传感器/执行器单独正确，再谈 PID**。
> 每一步都有明确的"通过标准"，不通过就不要进下一步。

---

## 0. 工具准备

- 电脑装好 CCS（或只用 `tools/build.ps1` 编译）；
- USB-C 数据线（能传数据，不是纯充电线）；
- 串口助手（波特率 115200）或 `tools/telemetry.py`；
- 卷尺（≥3m）、美纹纸/黑胶带、白纸、直角尺、激光笔；
- 满电电池、充电器。

编译：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1
```

产物在 `build\2024_H.out` / `.hex`。

烧录（任选其一）：

1. **CCS**：导入 `firmware` 工程 → Build → Debug/Flash；
2. **UniFlash/DSLite**：选 MSPM0G3507，加载 `.out` 或 `.hex`；
3. **立创开发板工具**：按地猛星 wiki 的 USB/BSL 烧录方式（PA18 上电为低）。

## 1. 静态检查（不装轮子）

### 1.1 主板与显示

上电后：

- OLED 显示开机画面约 1s，然后进入状态页；
- 串口每 20ms 一行 `$D,...`；
- 按 K4 能切换三页（状态 / PID / 灰度柱状图）。

**通过标准**：三页都能显示，按键有"滴"声。

### 1.2 电机方向

拆下轮子（或架空），串口发：

```
m300,300
```

两个电机都应**朝前**转（轴端看逆时针/顺时针以装轮后为准）。若某个反转：

- 改 `board.h` 的 `MOTOR_L_INVERT` / `MOTOR_R_INVERT`（0↔1）；或
- 对调该电机在 TB6612 上的两根线。

发 `n` 停止。

> `m` 是开环调试命令，会绕过所有闭环；**正式跑车时绝不能用**。

### 1.3 编码器方向与计数

装回轮子，手推车前进 1m，观察串口 `vL/vR`：

- 都应为正；若某个为负，改 `ENC_L_SIGN` / `ENC_R_SIGN`（+1↔-1）；
- 记下 1m 的计数（可用 `s` 字段，或临时在 `bsp_encoder.c` 打印 `encoder_count_l()`）。

标定 `WHEEL_D_CM`：

```
实际值 = 标称值 × (设定距离 / 实测距离)
```

例如设定跑 100cm，实测 96cm（走短了），说明程序认为的轮径偏小 → 把 `WHEEL_D_CM` 从 6.5 改成 `6.5×100/96 = 6.77`。反复 2 次，直到 200cm 误差 <1cm。

> 更严谨：直接改 `COUNTS_PER_CM`，但改轮径更直观，且 `ENC_CPR` 会自动跟着变。

### 1.4 灰度极性、顺序、阈值

1. 把车放在白纸上：柱状图 8 格全灭，`RAW 0x00`；
2. 用黑胶带依次划过 CH0→CH7：对应格依次亮；
3. 若"白底全亮、黑线灭"，把 `GRAY_ACTIVE_HIGH` 改成 0；
4. 若 CH0 亮的是最右边，说明排线接反：把 8 根线倒序，或把 `bsp_gray.c` 的位映射反过来。

**通过标准**：黑线压在哪一路，柱状图对应位置亮，且位置 `POS` 的符号正确（线在右，POS 为正）。

### 1.5 陀螺仪

1. 串口 `imu_frames` 应持续增长（100 帧/s 左右）；
2. 车静止 10s，`yaw` 漂移应 <0.5°；
3. 手拿车**左转**，`yaw` 应**增大**；若减小，改 `IMU_YAW_SIGN = -1`；
4. 发 `z` 可把当前航向清零。

**通过标准**：左转增大、静止稳定、`IMU OK`。

## 2. 轮速环整定

目标：给定 `v_ref`，实测 `v` 在 0.15s 内跟上，超调 <10%，稳态误差 <1cm/s。

方法：

1. 架空车，串口发 `m400,400`，看 `vL/vR` 是否接近（两轮负载不同，允许 5% 差异）；
2. 用 `v<kp>,<ki>` 在线改，例如 `v3.2,18`；
3. 阶跃测试：发 `m0,0` 再 `m800,800`，看遥测曲线（`tools/telemetry.py`）。

经验值：

- `Kp` 太大：占空比抖动、电机尖叫、电流大；
- `Ki` 太大：低速爬行、停车后"蠕行"；
- 默认 `3.2 / 18` 适合 1:30 N20 + 65mm 轮；换电机要重调。

> 正式跑车时轮速环由 `control.c` 的 `speed_loop()` 调用，`m` 命令只用于开环检查。

## 3. 直线航向环（第 1 题）

场地：找一条 3m 长的平整地面，用美纹纸标出起点和 100cm 终点（不需要黑线）。

步骤：

1. 车头对准终点，发 `1`（选题 1）再按 K2；
2. 观察车是否走直线、到 B 是否停住；
3. 用 `h<kp>,<ki>,<kd>` 调，默认 `0.020,0.0015,0.0025`。

判据：

| 现象 | 调整 |
|---|---|
| 左右画龙 | 减小 `Kp`，增大 `Kd` |
| 反应迟钝、慢慢偏 | 增大 `Kp` |
| 停车前"点头" | 正常（减速规划），不用调 |
| 一直朝一边偏 | 起跑没对准，或陀螺仪零漂；先 `z` 再发车 |
| 到 B 停早了/晚了 | 标定 `WHEEL_D_CM`（见 1.3） |

**通过标准**：100cm 横向偏差 <3cm，停车点误差 <2cm，时间 <8s。

> 第 1 题 20 分，其实只要"能停住、不跑偏"就能拿。不要在直线上花太多时间。

## 4. 圆弧循迹（第 2 题）

场地：用白布/白纸 + 黑胶带做一段 R=40cm 的半圆弧（线宽 18mm），或直接去赛场试跑（允许赛前试跑）。

步骤：

1. 先低速：把 `V_TASK2` 改成 20，`V_ARC_SCALE` 0.8；
2. 车放在弧起点，切线方向摆放，发 `2`；
3. 看车是否能贴着弧走、出弧后是否直行；
4. 调 `l<kp>,<ki>,<kd>`，默认 `0.010,0.00002,0.0006`。

判据：

| 现象 | 调整 |
|---|---|
| 进弧就往外冲 | 进弧速度太高 → 降 `V_TASK2`；或增大 `Kp` |
| 弧上左右摆 | 减小 `Kp`，增大 `Kd`；检查灰度间距是否 >15mm |
| 出弧后画龙 | 航向环 `Kp` 太大，或出弧时航向误差大 |
| 弧走一半丢线 | 探头太低/太高；黑线反光；降速 |

**通过标准**：整圈不脱线，时间 <25s。

### 4.1 第 2 题联调

第 2 题没有转向，B→C、D→A 都是相切的，理论上"直线+圆弧+直线+圆弧"即可。常见问题：

- **B 点没进弧**：车在 B 点时灰度条已经过了弧起点（探头前伸 8cm），程序在里程到 100cm 才切 ARC，此时探头已在弧上，没问题；若冲过头，把 `SENSOR_AHEAD_CM` 调准，或把 ARC 段的起始判定提前 2cm（改 `mission.c` 的 `remain <= 0.8f` 为 2.0f，仅 ARC）。
- **C 点出弧后不走直线**：出弧航向应为 180°，程序在 ARC 段用切线 `180°` 结束，若实际差 2°，直线段航向环会拉回，允许。

## 5. 转向与 8 字（第 3 题）

### 5.1 单次转向

车放在 A，车头朝 C（-38.66°），发 `3`：

1. 车沿对角线到 C；
2. 在 C 点内轮停、外轮正转，左转 38.66°；
3. 进右弧，走 180° 到 B；
4. 左转 38.66°，沿对角线到 D；
5. 右转 38.66°，进左弧，走 180° 回 A 停车。

调 `t<kp>`（默认 1.1）：

| 现象 | 调整 |
|---|---|
| 转过量 | 减小 `kp`；或把 `mission.c` 的 `1.2f` 死区加大到 1.5 |
| 转不到位 | 增大 `kp` |
| 转完车"跳一下" | 正常（内轮从 0 恢复），下一段航向环会收 |
| 在 C 点没进弧 | 转向后车位置偏了 4cm，灰度捕获窗口 ±5cm，临界；把 `V_TASK3` 降到 30 试试 |

**通过标准**：一圈回到 A，投影盖住 A，时间 <30s。

### 5.2 第 4 题 4 圈

1. 先把第 3 题跑稳（连续 3 次成功）；
2. 再把 `V_TASK4` 从 40 逐步提到 55–60，`V_ARC_SCALE` 0.85；
3. 观察第 3、4 圈是否在 A 点转向时"扫"到边界——若会，降低 `V_TASK4` 或提前减速（`mission.c` 的 `seg_v_end` 已对最后一圈 ARC 做 0 减速、对圈间 ARC 做 16cm/s 减速）。

**通过标准**：连续 4 圈不碰边界、不停错点，时间 <70s（目标 50–60s）。

### 5.3 多圈误差为什么不会累积

每圈：

- 在 A 点用**绝对航向**转向（`H_AC_DEG`），把上一圈航向误差清零；
- 每段起点 `s=0`，把里程误差清零；
- 圆弧段用灰度修横向，不依赖上一圈的绝对位置。

所以第 4 圈和第 1 圈一样准。

## 6. 串口遥测与画图

```powershell
python tools\telemetry.py --port COM5 --log run.csv
```

- 实时打印解析后的关键量；
- `--task 3` 可直接发命令启动；
- 有 matplotlib 时 `--plot` 画 yaw/偏差/速度曲线。

字段含义见 README 第 5 节。

**看什么**：

- `vref` 与 `vL/vR` 的跟随差 → 轮速环；
- `yaw` 与目标航向的差 → 航向环；
- `line_mm` 是否在 ±15mm 内 → 循迹；
- `seg` 是否按 0→1→2… 正常推进 → 状态机。

## 7. 参数整定顺序（重要）

1. `WHEEL_D_CM`（距离）—— 决定所有节点位置；
2. `V_TASK*`（速度）—— 先慢后快；
3. 轮速 `sp_kp/sp_ki`；
4. 直线 `hd_kp/hd_ki/hd_kd`；
5. 循迹 `ln_kp/ln_ki/ln_kd`；
6. 转向 `turn_kp`；
7. 最后才调 `V_TASK4` 冲速度。

**不要同时改两个参数**，否则永远不知道是谁起的作用。

## 8. 故障排查（按现象）

| 现象 | 可能原因 | 排查 |
|---|---|---|
| 上电 OLED 不亮 | I2C 地址不对/没上拉/供电 | 换 0x3D；加 4.7k；量 3.3V |
| 串口无数据 | 没插 CH340 驱动/USB 线是充电线 | 设备管理器看 COM 口 |
| 发车没反应 | 陀螺仪没数据（`IMU LOST`） | 检查 TX/RX、波特率；K2 会拒绝发车 |
| 车不动但轮子有劲 | STBY 没拉高/电机线松 | 量 PB6=3.3V；查 AO1/AO2 |
| 车往一边跑 | 起跑没对准/轮径不一致/陀螺仪零漂 | 重新 `z`；标定；检查轮胎 |
| 到点不停 | `WHEEL_D_CM` 偏小/编码器丢脉冲 | 标定；检查编码器线 |
| 圆弧脱线 | 速度太高/灰度间距太大/探头脏 | 降速；擦探头；换 15mm 间距 |
| 第 4 题第 3 圈出界 | 陀螺仪漂移/转向误差累积 | 每圈绝对航向已处理；换 HWT101；降速 |
| 跑一半复位 | 电池压降/电机干扰 | 满电；加电容；电机线远离 MCU |
| 转向时车"蹦" | 内轮从 0 突然给力 | 正常；可把 `turn_kp` 调小 |

## 9. 现场快速复调（10 分钟）

比赛现场只给 10 分钟调试：

1. 上电，看 OLED/串口是否正常（1min）；
2. 手推车，确认 `vL/vR` 正、灰度有反应（1min）；
3. 跑第 1 题，确认能停（2min）；
4. 跑第 2 题，确认整圈（3min）；
5. 跑第 3 题，确认 8 字（3min）；
6. 视情况跑第 4 题 1 圈，不要跑 4 圈浪费电。

**不要在现场大改 PID**；只微调 `V_TASK*` 和起跑位置。
